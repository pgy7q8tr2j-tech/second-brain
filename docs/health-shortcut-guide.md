# iPhoneショートカット手順書：ヘルスケアの数値を第二の脳へ送る

Apple Watch → iPhoneヘルスケア → **このショートカット** → `POST /api/health/ingest` → Neon → claude.ai の相談で Claude が読む。

Claude Code はショートカットを直接作れないため、iPhoneの画面に沿った手順書です。
**⚠️ と書いた「未確認」の箇所は、実機を見ながら確認してください。** 分からなければその画面を伝えてくれれば一緒に詰めます。

---

## 0. 事前に用意するもの

| 項目 | 値 |
|---|---|
| 送信先URL | `https://second-brain-six-ashy.vercel.app/api/health/ingest` |
| 認証ヘッダ | `Authorization: Bearer <HEALTH_INGEST_TOKEN>` |
| トークン | **ステップ3で `openssl rand -hex 32` で作った64文字**（＝Vercelの `HEALTH_INGEST_TOKEN`）。MCP用トークンとは**別物**です。 |

> ⚠️ ここで使うのは **ingest用トークン（HEALTH_INGEST_TOKEN）** です。コネクタで使ったMCPトークンではありません。混同しないでください。

---

## 1. 送るデータの形（完成イメージ）

ショートダットは最終的に、次の形のJSONを本文にしてPOSTします。**今日と昨日の2日分**を送ります（夜遅くの分を翌日に埋めるため）。

```json
{
  "sent_at": "2026-10-08T21:30:00+09:00",
  "tz": "Asia/Tokyo",
  "days": [
    {
      "date": "2026-10-08",
      "active_energy_kcal": 512.3,
      "basal_energy_kcal": 1560,
      "steps": 8123,
      "walking_distance_km": 5.9,
      "body_mass_kg": 72.4
    },
    {
      "date": "2026-10-07",
      "active_energy_kcal": 470.1,
      "basal_energy_kcal": 1555,
      "steps": 10231,
      "walking_distance_km": 7.2,
      "body_mass_kg": 72.6
    }
  ]
}
```

### 項目と、対応するヘルスケアの種類・単位

| JSONのキー | ヘルスケアの種類（日本語表示） | 単位 | 集計方法 |
|---|---|---|---|
| `active_energy_kcal` | アクティブエネルギー | kcal | その日の**合計** |
| `basal_energy_kcal` | 安静時エネルギー | kcal | その日の**合計** |
| `steps` | 歩数 | 歩(count) | その日の**合計** |
| `walking_distance_km` | ウォーキング+ランニングの距離 | **km** | その日の**合計** |
| `body_mass_kg` | 体重 | kg | **最新の1件**（合計しない） |

> サーバーは単位を上の通り固定で保存し、**数値の変換はしません**。そのため、ショートカットが返す数値が上の単位（kcal / km / kg / 歩）と一致している必要があります。ステップ10で、届いた値がヘルスケアアプリの表示と合うか必ず確認します。
> - 距離が**メートル**で返る場合、5.9km が 5900 になり、サーバーの上限(500km)に引っかかって 400 エラーになります（＝異常値ガードで気づけます）。その場合は「数値を1000で割る」アクションを挟みます。⚠️ 距離の単位は実機で要確認。
> - エネルギーが **kJ** で返る環境だと、数値がkcalより大きくなります。ステップ10の突き合わせで気づけます。⚠️ エネルギーの単位も要確認。

## 2. ショートカットを新規作成

1. 「ショートカット」アプリを開く → 右上 **＋** で新規作成。
2. 名前を付ける（例：`ヘルスケアを第二の脳へ送信`）。

以降、アクションを順に追加していきます。アクション検索は画面下の検索窓から行います。

---

## 3. 「今日」の各項目を取得する

まず**今日のアクティブエネルギー合計**を作り、同じ要領で他も作ります。

### 3-1. 今日の開始日時を用意（日付の絞り込み用）
- アクション「**日付**」を追加 → 値を「**現在の日付**」にする（なければ「現在の日付を取得」系アクション）。
- ⚠️ 未確認：ヘルスケア検索側で直接「**今日**」を指定できるUIがある場合は、この日付アクションは不要です。実機の「ヘルスケアサンプルを検索」の絞り込み条件に「今日」「今日の開始」等があるか確認してください。

### 3-2. アクティブエネルギーのサンプルを検索
- アクション「**ヘルスケアサンプルを検索**」を追加。
  - 種類（タイプ）：**アクティブエネルギー**
  - 絞り込み条件：**開始日**（または日付）が **今日**（＝今日の0:00〜現在）。
    - ⚠️ 未確認：この絞り込みの正確な項目名・指定方法（「開始日 は 今日」なのか「日付 が 次の期間内：今日」なのか）。実機で設定して、3-4の結果が妥当か確認します。
  - 並べ替え・上限：合計を出すだけなら不要。

出典（アクションの存在）：Apple公式「[検索アクション](https://support.apple.com/ja-jp/guide/shortcuts/apd3c845e881/ios)」

### 3-3. 合計を計算
- アクション「**統計を計算**」を追加（英語名 Calculate Statistics）。
  - 操作：**合計**
  - 入力：3-2の「ヘルスケアサンプル」
- ⚠️ 未確認：このアクションの正式な日本語名。公式ページで明示を確認できませんでした。もし「統計を計算」が見つからない場合は、検索窓に「合計」「統計」「Calculate」と入れて出てくるアクションを探してください。見つからなければ画面を教えてください。

### 3-4. いったん結果を確認（任意だが推奨）
- この時点で一度ショートカットを実行し、3-3の合計値がヘルスケアアプリの「今日のアクティブエネルギー」と近いか見ておくと、後の不具合切り分けが楽です。

### 3-5. 安静時エネルギー・歩数・距離も同様に
- 3-2〜3-3を繰り返し、種類を **安静時エネルギー / 歩数 / ウォーキング+ランニングの距離** に変えて、それぞれの**今日の合計**を作ります。

### 3-6. 体重は「最新の1件」
- 「ヘルスケアサンプルを検索」種類＝**体重**。
  - 並べ替え：**開始日の新しい順**、**上限：1件**。
  - 合計はしない。その1件の値を使う。
- ⚠️ 未確認：並べ替え項目名と上限設定の場所。実機で確認。

> 各合計・体重の結果は、次の辞書で使うため「変数に追加」しておくと分かりやすいです（例：`今日_active`, `今日_basal`, `今日_steps`, `今日_dist`, `今日_weight`）。

## 4. 「昨日」の各項目を取得する

3と同じ手順を、日付条件だけ「**昨日**」にして繰り返します。
- 「ヘルスケアサンプルを検索」の絞り込みを「昨日（昨日の0:00〜24:00）」にする。
- ⚠️ 未確認：「昨日」をどう指定するか（「日付」アクションで現在日から1日引く／検索側に「昨日」オプションがある等）。実機で確認。
- 結果を `昨日_active` などの変数に入れます。

## 5. 日付文字列と送信時刻を作る

サーバーに渡す `date`（YYYY-MM-DD）と `sent_at`（タイムゾーン付きISO 8601）、`tz` を用意します。

- **今日の日付文字列**：アクション「**日付をフォーマット**」
  - 入力：現在の日付
  - 形式：カスタム → `yyyy-MM-dd`
- **昨日の日付文字列**：現在の日付から「1日」引いた日付を同じく `yyyy-MM-dd` でフォーマット。
- **sent_at**：現在の日付を **ISO 8601（タイムゾーン付き）** でフォーマット。
  - 「日付をフォーマット」にISO 8601オプションがあればそれを使用。無ければカスタムで `yyyy-MM-dd'T'HH:mm:ssXXX`。
  - ⚠️ 未確認：ISO 8601のタイムゾーン表記（`+09:00`）が付く形式になっているか。サーバーは**タイムゾーン必須**（Z または ±hh:mm）です。付いていないと400になります。実機で生成結果を確認。
- **tz**：`Asia/Tokyo` を文字列で入れる。
  - ⚠️ 渡英後（2026-11-29以降）：iPhoneのタイムゾーンが自動で英国時間に変われば、「今日」の区切りも自動でそちらに切り替わります。`tz` を動的に入れられるならそれが理想ですが、手入力で `Asia/Tokyo` を使っている場合は**渡英後に `Europe/London` へ直す**のを忘れないでください。`date` の区切り自体は端末のタイムゾーンに従うので、`tz` はあくまで記録用ラベルです。

> 💡 タイムゾーンの考え方：`date` は「端末の現在タイムゾーンで区切った日付」をそのまま送ります。サーバーは変換しません。だから端末の設定が英国時間になれば、自動的に英国時間の1日で区切られます。

## 6. 「辞書」でJSONを組み立てる

- アクション「**辞書**」を追加し、第1節のJSON構造を作ります。
  - `sent_at`：テキスト → 5で作ったISO 8601
  - `tz`：テキスト → `Asia/Tokyo`（または動的なタイムゾーン名）
  - `days`：**配列**
    - 配列の要素1（今日）：辞書
      - `date`：今日の日付文字列
      - `active_energy_kcal`：`今日_active`
      - `basal_energy_kcal`：`今日_basal`
      - `steps`：`今日_steps`
      - `walking_distance_km`：`今日_dist`
      - `body_mass_kg`：`今日_weight`
    - 配列の要素2（昨日）：同様に `昨日_*`

> 数値が文字列として入っても大丈夫です。サーバーは `"512.3"` のような**数値文字列も受け付けて変換**します（カンマ付き `"8,123"` も可）。なので「辞書の数値が文字列で送られるか」は気にしなくて構いません（設計で対応済み）。

> 体重など、その日にデータが無い項目は**キーごと省略**するか空にしておけばOKです。`null`・未送信は「送られていない」として既存値を保持します（勝手に消えません）。

## 7. 「URLの内容を取得」で送信（POST）

- アクション「**URLの内容を取得**」を追加。
  - URL：`https://second-brain-six-ashy.vercel.app/api/health/ingest`
  - 「**詳細を表示**」を開く：
    - 方法（Method）：**POST**
    - ヘッダ：
      - キー `Authorization` / 値 `Bearer <HEALTH_INGEST_TOKEN>`
      （`Bearer ` の後ろにステップ3の64文字トークン。`Bearer` と トークンの間は半角スペース1つ）
    - 要求の本文（Request Body）：**JSON**
    - 本文の中身：6で作った**辞書**を指定
- ⚠️ 未確認：
  - 初回実行時に「"ショートカット"が …に接続しようとしています」等の**接続許可**が出るか。出たら許可してください。
  - 自動実行（オートメーション）時にこの許可で止まらないか。→ まず手動実行で許可を済ませておけば、以後は止まらないはずです（実機で確認）。

### 送信結果の確認（手動実行用）
- 「URLの内容を取得」の後に「**クイックルック**」アクションを足しておくと、サーバーの応答が見えます。
  - 成功：`{"ok":true,"upserted":件数,"skipped":件数}`
  - 401：トークンが違う／`Bearer ` の付け方を確認
  - 400：日付やタイムゾーン、異常値（距離がメートル等）を確認
- 動作が安定したらクイックルックは外してOK。

## 9. オートメーションで自動実行（ステップ11に対応）

「ショートカット」アプリ下部の「**オートメーション**」タブ → **＋** → 「**個人用オートメーションを作成**」。

### 主トリガー：Claudeのアプリを開いたとき
- トリガー：「**App**」→ Claude を選択 → 「**開いている**」。
- 実行内容：このショートカットを実行。
- 「**実行の前に尋ねる**」を**オフ** → 「**尋ねない**」にする（確認なしで実行）。
  - 出典：Apple公式「[オートメーションの実行](https://support.apple.com/ja-jp/guide/shortcuts/apd602971e63/ios)」（自動実行できるトリガーに「App」「充電器」等が含まれる。個別アクションで設定が必要な場合がある旨も記載）

> この「Appを開いたとき」が主トリガーである理由：相談のたびに、ロック解除済みの状態で最新値が届くためです。

### 補助トリガー：充電器に接続したとき
- 別のオートメーションを作成 → トリガー「**充電器**」→ 「接続したとき」。
- 同じショートカットを実行、「尋ねない」。

### 任意：時刻トリガー（ロック中に動くか試す）
- トリガー「**時刻**」で夜の定時（例：就寝前）を設定。
- ⚠️ 未確認（重要）：**iPhoneがロック中はヘルスケアデータが暗号化**されており、ロック中の自動実行では**ヘルスケアを読めない可能性が高い**です（出典：Apple「[プライバシー機能](https://www.apple.com/ph/privacy/features/)」＝ロック中はヘルスケアが暗号化される）。
  - まず試してみて、ロック中でも正しい値が届けば採用、ダメなら主トリガー（Appを開いたとき）に任せる方針で問題ありません。
